1. Visión y ObjetivoPropósito: Conectar a administradores de predios de fútbol amateur con organizadores de partidos y jugadores individuales. Resuelve dos dolores centrales: para los predios, la desorganización de reservas y turnos caídos; para los jugadores, la dificultad de completar el equipo a último momento ("falta uno").Criterio de éxito del MVP: Un organizador puede ver una cancha en el mapa, solicitar un turno subiendo comprobante de seña y, si le falta gente, activar una alerta geolocalizada ("Radar Falta 1") que notifique a jugadores disponibles cercanos para que se sumen al partido. El dueño de la cancha puede aprobar la reserva desde su panel con un clic.2. Roles y PermisosVisitante: Puede explorar el mapa de canchas, ver disponibilidad horaria general y registrarse.Jugador / Organizador:Puede armar su perfil deportivo (posición, pierna hábil, zona).Puede reservar turnos en predios adjuntando comprobante de transferencia/seña.Puede crear una convocatoria de "Falta 1" en un turno reservado.Puede postularse para sumarse como suplente a partidos con alerta activa.Dueño / Administrador de Predio:Puede gestionar el perfil del complejo (fotos, dirección en mapa, alias/CBU de pago, precios, tipos de cancha: F5/F8).Configurar grilla horaria semanal y bloquear/liberar turnos manualmente.Aprobar o rechazar reservas revisando el comprobante adjunto.Superadmin: Acceso global a métricas de adopción, alta y verificación de predios, y moderación de reportes de usuarios.3. Reglas de Negocio Estrictas (Lo que la IA NO debe inventar)No-Show y Bloqueo de turnos: Una solicitud de reserva sin comprobante adjunto no es válida y no puede pasar a estado pendiente. Al cargarse el comprobante, el turno queda reservado provisionalmente por un lapso máximo de 15 minutos; si el dueño no aprueba o rechaza en ese lapso, el sistema notifica al dueño, pero no cancela arbitrariamente sin aviso.Alertas "Falta 1": Solo un usuario con turno confirmado o el dueño del predio pueden activar un radar de suplentes para ese horario.Eliminación y bajas: No existe el borrado físico (hard-delete) de reservas ni usuarios; todo se maneja con soft-delete o cambios de estado (cancelado, inactivo) para preservar el historial de cancelaciones y reputación.Pasarela de pago: El MVP no procesa dinero en la app. No generar código para cobros automáticos con tarjetas ni comisiones bancarias; todo se resuelve mediante visualización de comprobante de transferencia directa.7. Stack Tecnológico ElegidoFrontend: PWA construida con Vite + React (o Next.js PWA) + Tailwind CSS + Lucide Icons.Mapas: Leaflet / Mapbox GL JS (OpenStreetMap para mantener costos en cero).Backend y Base de Datos: Supabase (PostgreSQL con extensiones PostGIS para cálculo de distancias por radio/km) o Firebase (Firestore + Cloud Storage para las imágenes de los comprobantes).Autenticación: Supabase Auth o Firebase Auth (Login con Teléfono / SMS o Google Auth + Password).Hosting / Despliegue: Vercel o Cloud Run / Netlify.
